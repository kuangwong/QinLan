# 拾日 · 鸿蒙原生客户端

根据根目录 [PLAN.md](../PLAN.md) 与 [网页原型](../原型/README.md) 开发的 ArkTS / ArkUI Stage 工程。保留鼠尾草绿、暖白、淡紫色和中文交互，手机端采用「待办 / 名字灵感 / 名字日历」底部导航。

逐项实现证据、检查结果与尚未通过的验收项见 [鸿蒙开发验收记录](ACCEPTANCE.md)。

## 当前实现

- 待办新增、编辑、完成、恢复、删除，按清单、负责人、状态、关键词过滤并按截止时间排序。截止时间可通过系统日期/时间选择器填写、手动输入或清除。
- 个人清单、七天有效邀请码、确认加入、撤销邀请、成员退出与移除、所有权转让和清单删除。移除或退出成员后，其未完成待办变为未分配；恢复已完成的历史任务时，已退出的负责人也会取消分配。
- 完整名称抽取、2–3 个有序词组组合；创建、编辑、删除个人词库，粘贴文本和通过系统文件选择器导入 UTF-8 TXT，去除空行和重复项。每组最多 10000 个候选、每个候选最多 300 字符，三个词组拼接的记录最多 900 字符；本机与联网模式使用同一导入校验。
- 名字仅在手动保存时写入日历；记录保存来源库名称、模式、保存时本地日期和 UTC 时间。词库变更不改写历史；支持同日多条、跨月浏览、删除自己的记录及向共享清单分享。
- 联网账号入口和 `/api/v1` 客户端：注册、登录、退出、手动刷新、回到前台/切换主页面刷新，查看共享清单时每 30 秒刷新。请求失败保留输入；版本冲突提供「载入最新内容」，确认后才替换草稿，普通刷新不自动修改编辑版本号。会话失效提供「重新登录」，离开草稿前同样确认。不在离线时写入修改；写入已成功但刷新失败时，先刷新确认结果再继续操作。
- 登录令牌由 Asset Store Kit 保存在设备安全存储中，安全存储失败不会回退到明文文件。服务器地址只在首次连接时填写；恢复已有会话时从安全存储读取连接信息。
- 独立本机体验模式使用私有目录：临时文件写入、fsync 后替换正式快照，保存成功后才发布状态；读取失败保留文件，不覆盖为示例数据。截止时间输入按本地时区解释，存储为 UTC，显示时转换回设备时区。
- 登录、退出和切换体验成员时重置搜索、筛选、草稿及生成结果。保存或同步期间禁用表单，避免请求提交后输入被继续更改；进入清单或日历视角时立即刷新。词库、成员和分享变更使用快照版本更新卡片。键盘采用页面缩放避让，筛选与成员操作按钮支持窄屏换行；实际设备布局仍待验收。
- 主要操作与底部导航使用最小触控高度，文字可自然撑高；待办、词库与记录操作支持换行。表单保留字段标签并添加朗读名称；日历朗读完整日期、选中状态和记录状态，字体放大时可横向滚动。窗口显式采用系统非全屏布局避让状态栏与导航区域，实际安全区和无障碍体验需设备验收。
- 系统通知授权入口与日历代理提醒适配：新增、完成、删除、修改、切换体验成员及回到页面时对比系统提醒，取消失效项并补充新项。并发更新按最新快照串行处理，退出会等待清理；清理失败在登录页保留重试入口。普通应用最多安排最近 30 项，超出会显示未安排数量；需要再次打开应用补充。外部接口传入的秒数会保留，毫秒向上取整到秒，避免提前触发。API 12 的代理提醒需真机验证，官方文档标注 API 20 起支持模拟器。

**已通过 HarmonyOS 5.0.1 / API 13 原生编译并生成未签名 HAP；尚未完成设备验收与鸿蒙 7 适配验证。** 联网模式连接 [Fastify/PostgreSQL 服务](../server/README.md)，使用真实账号与服务端权限；服务与实际客户端业务层已通过真实 HTTP 联调。本机体验模式的三个成员共用此设备文件，体验数据和邀请码不会自动上传，也不能用于跨设备协作。NetworkKit、Asset Store 和 ArkUI 在目标设备上的行为仍待验证。

## 连接协作服务

先按 [后端说明](../server/README.md) 启动数据库、迁移并运行服务，局域网联调将服务 `HOST` 设置为 `0.0.0.0`。应用登录页填写电脑局域网地址，例如 `http://192.168.1.10:3000`，注册新账号或使用初始化的 `xiaoman` / `yizhou` 账号及自行设置的密码。正式环境使用 HTTPS 地址。

默认登录页可选择「先体验本机版本」。本机模式与联网模式的数据独立；联网模式不会把本机的演示身份当成真实账号。邀请码原码只在刚生成时显示，离开后可撤销或重新生成，旧码随之失效。

## 没有鸿蒙开发环境时

Node.js 22+ 可以运行下列检查，不能生成或运行鸿蒙安装包：

```bash
cd harmony
pnpm install --frozen-lockfile
pnpm test
pnpm check:project
```

测试工具从实际 `domain/*.ets` 生成临时 TypeScript 副本，仅改写文件扩展名和导入路径，严格类型检查后执行 Node 测试。它验证业务行为、持久化事务、登录会话、失败与冲突处理及提醒对账；不检查 ArkUI DSL、平台接口、文件系统适配或真实通知。`check:project` 检查入口和资源引用，也不替代原生编译。后端的 `pnpm test` 另外验证实际 `OnlineClient.ets` 与真实 PostgreSQL/HTTP 服务的兼容性。

## 命令行原生构建

已在 Linux x64 验证官方 Command Line Tools `5.0.5.310`（Hvigor / OHOS 插件 `5.13.2`、ohpm `5.0.10`）、HarmonyOS SDK `5.0.1.115`（API 13）和 JDK `17.0.2`。工具包下载地址：[华为官方仓库](https://repo.huaweicloud.com/harmonyos/ohpm/5.0.5/commandline-tools-linux-x64-5.0.5.310.zip)，官方 SHA256 为 `f5b4240807c24457294b6469c6d39c1c00b5d9e06c391852d633a5da7ff28c6d`。工具与 JDK 安装在仓库之外，不随源码分发。

```bash
cd harmony
export HARMONY_COMMAND_LINE_TOOLS=/path/to/command-line-tools
export JAVA_HOME=/path/to/jdk-17
pnpm build:native
```

命令会安装 ohpm 依赖、清理旧产物、编译 ArkTS/ArkUI/资源并打包；失败返回非零状态。产物为 `entry/build/default/outputs/default/entry-default-unsigned.hap`，**未签名，不能直接安装到普通设备**。构建工具会提示缺少签名；旧工具另有对 `0.1.0` 版本号的误报和同名应用图标资源提示，均未阻止打包。编译成功仅验证静态接口与打包，不证明安全存储、网络和提醒已在设备运行。

## 设备平台自动化测试

`entry/src/ohosTest/` 使用 Hypium `1.0.21` 和系统 TestKit，直接调用实际 `FileStorage`、`LocalStore` 和 `AssetSessionVault`。六项用例覆盖中文与表情文件读写、替换较短快照、真实磁盘重开、非法事务回滚、磁盘写入失败后重试、中断临时文件恢复、损坏快照保留，以及安全凭据重开、覆盖与删除。设备需已解锁；安全存储不可用时测试应失败，不会跳过或回退到明文。

沿用上述环境变量，先构建应用，再编译测试包：

```bash
pnpm build:native
pnpm build:device-tests
```

第二条命令强制重新编译测试目标，保留应用产物，并生成 `entry/build/default/outputs/ohosTest/entry-ohosTest-unsigned.hap`。应用与测试目标均需配置相同开发签名。连接设备后，在 DevEco Studio 中对 `entry/src/ohosTest/ets/test/Platform.test.ets` 选择 **Run**，查看 Hypium 六项结果。也可在两个已签名包安装后执行：

```bash
hdc shell aa test -b com.qinlan.shiri -m entry_test -s unittest OpenHarmonyTestRunner
```

测试为每次运行创建随机文件名和随机 Asset 别名，并在结束时清理，保留正常快照与登录凭据。测试代码仅进入 `ohosTest` 产物。**当前已验证测试包可编译，尚无连接设备，因此以上设备运行命令及六项测试结果均待验证。** `pnpm test` 的 Node 结果不能代替这些平台用例，也不能代替 NetworkKit、通知授权和提醒真机验收。

## 在 DevEco Studio 中运行

1. 在华为官方支持的开发主机上安装 DevEco Studio、HarmonyOS SDK 和设备工具；创建或连接模拟器/真机。工具下载入口：[HarmonyOS 开发工具](https://developer.huawei.com/consumer/cn/deveco-studio/)。当前工作区已准备命令行 SDK，可生成未签名包；没有 IDE 或已连接设备。
2. 用 **Open** 打开本目录 `harmony/`，等待 IDE 同步工程。若提示更新 Hvigor 模型，使用 IDE 的迁移工具并保持工程、插件与已安装 SDK 一致。`pnpm` 只安装本地测试工具，原生依赖由 IDE/ohpm 管理。
3. 当前 `build-profile.json5` 使用已实际编译通过的 **HarmonyOS 5.0.1 / API 13**，最低兼容版本为 **5.0.0 / API 12**；API 12 运行兼容性仍需设备验收。安装面向鸿蒙 7 的官方 SDK 后，用 IDE 的产品配置选择实际 SDK，并重新检查编译、权限与行为；**尚未声明鸿蒙 7 适配通过**。
4. 在 **Project Structure → Signing Configs** 中配置本机自动签名并选择设备。签名证书、密码和 `local.properties` 不应提交。工程未附带开发者证书。
5. 通过 IDE 的 **Build Hap(s)** 构建，再运行 `entry`。输出位于 `entry/build/default/outputs/default/`；当前已有命令行构建生成的未签名 HAP，配置签名后需重新构建用于设备安装。

## 首次原生验收

1. 使用两个真实账号登录两台设备；新增、修改、完成和恢复待办，刷新或重新启动确认服务端数据同步。使用系统选择器填写截止时间，确认取消不改写原输入，清除后不再安排提醒。输入无效日期、断网或发生版本冲突时应保留表单并提示；普通刷新后旧表单仍不能覆盖他人的修改，只有确认「载入最新内容」后才替换草稿。会话失效应显示重新登录入口，取消确认时输入保留。
2. 创建清单和邀请，用另一账号预览并确认加入；验证普通成员不能管理其他成员，退出后未完成任务取消分配。单独检查本机体验模式不读写服务器数据。
3. 导入含 BOM、空行和重复词的 TXT；检查两组/三组拼接以及完整名称抽取。超过候选数、候选长度或 UTF-8 字节上限时应给出提示且保留原输入；合法三组拼接的最长 900 字符结果可以保存并回看。
4. 生成后不保存，确认日历未变化；手动保存后修改或删除词库，确认历史保留；切换月份、成员及分享视角。
5. 为自己设置几分钟后的待办，在个人页授权通知。真机检查应用退至后台、进程终止后的提醒，以及完成、修改、删除后的取消/更新。拒绝权限应显示未启用，不能显示已安排。在提醒更新期间退出或切换成员，确认旧提醒最终清除；系统清理失败时登录页应允许重试。检查超过 30 项时按截止时间安排最近任务，后续同步补充剩余任务。
6. 编辑词库后返回列表，确认名称、模式与候选数更新；管理分享后检查按钮与分享范围更新；移除成员后检查清单人数。切换账号或本机体验成员，确认无上一成员的搜索、草稿或生成结果残留。
7. 在窄屏与横竖屏下检查系统返回、软键盘、长文本，以及状态栏、挖孔和底部导航区域。将系统字体调至最大后切回应用，确认主要按钮与底部导航不裁字、操作区可换行、日历可横向滚动且所有日期可点击。启用屏幕朗读，检查字段名称、底部导航选中状态、日期及名字记录状态；装饰符号不应重复朗读。当前已通过 API 13 编译，但没有设备，以上界面与平台验收均待执行。
